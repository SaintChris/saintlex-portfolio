I Contributed to the Awesome AI Second Brain Repo

June 10, 2026 · 8 min read

The Repo

awesome-second-brain is a curated comparison of AI second brain, memory, and knowledge systems. It maps ~20 tools across a 5-stage lifecycle: Collect, Organize, Evolve, Use, and Govern. Products are grouped by layer — end-to-end apps, local workspaces, agent memory layers, memory substrates, and platform baselines.

It's the kind of resource I wish existed when I was building my own stack. So when I found it, I didn't just read it — I contributed.

What I Added

Two PRs, 15+ files, covering:

  • Solution profile — Hermes Agent + Obsidian + Honcho as a fully local second brain stack
  • Setup guide — verified step-by-step instructions (~60 min), tested against my live deployment
  • Example workflow — daily email triage → Obsidian log → Honcho peer update
  • Comparison page — assembled local stack vs end-to-end app, compared across 9 dimensions
  • Updated existing pages — Hermes+LLM Wiki and Honcho profiles with current evidence
  • Cross-references — 6 comparison/index pages updated

Why This Stack

My setup is deliberately multi-layered:

  • Obsidian — human-owned knowledge vault, all local Markdown
  • Honcho — agent memory layer with peer cards, conclusions, semantic search
  • Hermes Agent — the runtime that connects everything
  • AgentMail — email as a first-class context source

It covers all 5 lifecycle stages. The tradeoff: higher setup burden (~$60 min) and operational responsibility. The payoff: full local ownership, inspectable files, zero cloud dependency.

The Contribution Process

What I learned contributing to someone else's repo:

  • Read CONTRIBUTING.md first — every repo has one. Follow it exactly.
  • Study existing pages — match the writing style, tone, and format.
  • Use their templates — don't invent your own structure.
  • Verify everything — test all commands against a live deployment before writing setup guides.
  • No sensitive data — never include API keys, credentials, or personal identifiers in public PRs.

What's Next

The PRs are open. If they merge, the repo will have the first fully documented local-first second brain stack with a verified setup guide. If not, the fork is public and the documentation stands on its own.

Either way, the process of contributing — reading a repo deeply, understanding its framework, and adding something genuinely useful — was worth it.
